# Hardware-Locked Licensing

Anti-piracy design for the vendor's own product: each license is bound to one
school computer and cannot be copied to another machine.

## Hardware fingerprint

`HardwareFingerprint.Compute` hashes four identifiers with SHA-256:

1. MAC address of the primary physical adapter
2. CPU ID (`Win32_Processor.ProcessorId` via WMI on Windows)
3. Motherboard serial (`Win32_BaseBoard.SerialNumber`)
4. System disk serial (`Win32_DiskDrive.SerialNumber`)

The WinUI app supplies `WmiHardwareInfoProvider`; `DefaultHardwareInfoProvider`
is a cross-platform fallback used by the demo and tests. Any component change
changes the fingerprint, invalidating the cached license.

## License keys

Format `XXXXX-XXXXX-XXXXX-XXXXX` over a 32-character alphabet (no 0/O/1/I),
with the last character a checksum so typos are caught offline before hitting
the license server. Keys are generated by the vendor tooling
(`LicenseManager.GenerateLicenseKey`).

## License file

`LicensePayload` (key, school name, fingerprint, issue + expiry timestamps) is
serialized to JSON and encrypted with **AES-256-GCM** — authenticated
encryption, so any byte-level tampering fails decryption and reports
`Tampered`. The AES key is derived (SHA-256) from a vendor secret embedded in
the application build.

## Validation states

| State | Meaning |
|---|---|
| `Valid` | Fingerprint matches, not expired |
| `NotActivated` | No cached license file |
| `HardwareMismatch` | License was activated on different hardware (copied install) |
| `Expired` | Past annual expiry — renewal required |
| `Tampered` | File corrupt, edited, or encrypted with a different secret |
| `TrialActive` / `TrialExpired` | 30-day trial window; a first-run stamp in the future (clock rollback) ends the trial |

## Activation flow

1. School purchases a license and receives the key.
2. First run online: key checked against the vendor license server (server-side
   verification is the vendor's dashboard; this repo implements the client side
   and the key/checksum, binding, and cache format).
3. Fingerprint captured, encrypted license file cached locally.
4. Subsequent runs validate offline: decrypt → compare fingerprint → check expiry.
5. Every activation/validation failure is written to `AuditLogs`.
